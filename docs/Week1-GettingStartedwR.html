Introduction

Why R?

  • R is an impressive, do-it-all software: loading spatial datasets, to fitting models, analyzing patterns, and creating publication-quality maps and plots.
  • reproducibility of data summaries and statistical analyses.
  • Automation: automates repetitive or mundane data processing tasks.
  • Open-source and free: constant updates contributed by scientists worldwide.

This introductory lab is a foundation for students who have not used R often, or who want to review the basics of data and spatial data structures. Everything in this deck runs in the browser, so nobody needs a working local install on day one.

Getting Help in R

  • To view documentation for any loaded function, use help() or ?:
?runif
help(runif)
  • help(package = "sf") lists every function in a package.
  • ??aggregate runs a fuzzy search.
  • Online resources are enormous.

In R you never have to memorise code. Help pages document the expected inputs (arguments) and the returned value.

R Syntax and Objects

Objects and Assignment

The core building block in R is the object. Objects hold data, models, and functions.

# Assign a sequence of numbers to an object named x
x <- 1:15

# Display it
print(x)
Note

<- is the assignment arrow. Typing the object’s name (or wrapping it in print()) displays its contents.

Objects Can Be Overwritten

x <- 1 + 15     # x is overwritten
y <- 5.2        # second object
z <- x^y        # third object

z

ls()            # list every object in the workspace

Notice that x now holds 16. The previous contents are gone without warning.

Objects Hold Any Type

x <- "wolverine"
y <- FALSE
z <- 42L

class(x)
class(y)
class(z)
Note

Character values are wrapped in quotation marks. TRUE and FALSE are not, and must be uppercase. The L suffix forces an integer.

Vectors

A vector is a sequence of values of one type. Build one with c().

mass_kg  <- c(38, 217, 7, 40)

Vectors

Math operations are done element by element and no loop is required.

mass_kg <- c(38, 217, 7, 40)

round(mass_lb, 1)

# Summary statistics

Simulating and Exploring a Dataset

Why Simulate?

  • Simulated data are reproducible
  • You know the truth, so you can check whether your analysis recovers it.

Every dataset in this lesson is generated by the code you can see. Nothing is loaded from disk or from the internet.

This is also how you check whether an estimator is behaving: simulate from known parameters, fit the model, and see whether the estimates land near the truth.

Summaries with aggregate()

Writing Your Own Function

detection_rate <- function(counts) {
  n_surveys <- length(counts)
  n_detect  <- sum(counts > 0)
  return(n_detect / n_surveys)
}

detection_rate(camera$count)

# Apply it by species
tapply(camera$count, camera$species, detection_rate)
Note

Saving functions in a separate script and calling source("my_functions.R") keeps analysis scripts readable.

Random Sampling and Distributions

What Is Randomness?

  • Every element has an equal and independent chance of being selected.
  • We cannot predict any single outcome with certainty — this is a random (stochastic) process.
  • Humans are poor random number generators. Ask ten people for “30 random points” and you will get suspiciously even spacing. That is why we use algorithms.

Uniform Distribution

Start with 100 draws from a uniform distribution between 0 and 10.

x_unif <- runif(n = 100, min = 0, max = 10)

summary(x_unif)
plot(x_unif, type = "h", col = "#333333",
     xlab = "Draw number", ylab = "Value",
     main = "100 uniform draws in the order sampled")

Compare your output with your neighbour’s. Did you get the same values?

Reproducibility with set.seed()

set.seed(2026)
a <- runif(5, 0, 10)

set.seed(2026)
b <- runif(5, 0, 10)

round(a, 4)
round(b, 4)
identical(a, b)
Note

set.seed() fixes the starting point of the random number generator. Put it at the top of any script you want to be reproducible.

Visualising the Distribution

set.seed(2026)
x_unif <- runif(n = 100, min = 0, max = 10)

hist(x_unif,
     col    = "#DFD1A7",
     border = "#333333",
     xlab   = "Value",

The bars are roughly level across the range because every value between 0 and 10 is equally likely. With only 100 draws the sampling noise is still obvious.

Poisson Distribution

Count data are often modelled as Poisson. It has a single parameter, the mean count λ (lambda).

set.seed(2026)
x_pois <- rpois(n = 250, lambda = 3.3)

table(x_pois)
hist(x_pois, 
     probability = TRUE,
     breaks = seq(-0.5, max(x_pois) + 0.5, 1),
     col = "#DFD1A7",
     border = "#333333",
     xlab = "Count", 
     main = "Poisson(lambda = 3.3)")
Note

For a Poisson, the variance equals the mean. Real count data are often overdispersed, i.e., more variable and that is when negative binomial models are useful.

Binomial and Bernoulli

The binomial arises when repeated trials have binary outcome. rbinom() takes the number of observations, trials per observation, and probability of success.

set.seed(2026)

# 10 observations, each of 5 trials, p = 0.25
x_binom <- rbinom(n = 10, size = 5, prob = 0.25)
x_binom

# Bernoulli: a single trial per observation
x_bern <- rbinom(n = 20, size = 1, prob = 0.35)
x_bern

barplot(table(factor(x_bern, levels = c(0, 1),
                     labels = c("Failure", "Success"))),
        col = c("#DFD1A7", "#70002E"),
        xlab = "Outcome", ylab = "Number of cases")
Note

This is the detection process behind occupancy models: each camera visit is a Bernoulli trial with detection probability p, and the number of visits with a detection out of K visits is binomial.

Graphics in R

Base Plotting Functions

  • plot(x, y) : scatter, line, or formula plots
  • hist(x) : distribution of one variable
  • boxplot(y ~ group) : distribution across groups
  • barplot(height) : tallies and totals
  • pairs(df) : all pairwise scatterplots, for spotting collinearity among predictors

Add-on packages include ggplot2 and lattice. We use base graphics here because terra and sf both plug straight into it.
