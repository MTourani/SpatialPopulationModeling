Introduction

Why R?

  • R is an impressive, do-it-all software: loading spatial datasets, to fitting models, analyzing patterns, and creating publication-quality maps and plots.
  • reproducibility of data summaries and statistical analyses.
  • Automation: automates repetitive or mundane data processing tasks.
  • Open-source and free: constant updates contributed by scientists worldwide.

This introductory lab is a foundation for students who have not used R often, or who want to review the basics of data and spatial data structures. Everything in this deck runs in the browser, so nobody needs a working local install on day one.

R Packages

  • R packages (libraries): bundles of functions, data, and documentation that extend R’s capabilities.
  • Spatial packages are catalogued on the CRAN Task View: Analysis of Spatial Data.
    • The two R spatial packages we lean on all semester:
    • sf: mostly for vector data (points, lines, polygons)
    • terra: mostly for raster data (grids, stacks)
  • Model fitting and post-processing
    • Nimble and coda
  • A few other occasional packages

Note that sf and terra have replaced the older sp and raster packages; sp was retired in 2023 and raster is in maintenance mode only.

Spatial Data in R

Two Data Types

  • Vector data represent discrete features with coordinates: points (nest sites, camera stations), lines (streams, roads, GPS tracks), polygons (home ranges, park boundaries, watersheds). Handled by sf, class sf / sfc.
  • Raster data represent a continuous surface as a regular grid of cells: elevation, canopy cover, temperature, predicted density. Handled by terra, class SpatRaster.
  • terra also carries its own vector class, SpatVector, so raster and vector operations can talk to each other without leaving the package.
ImportantCoordinate reference systems

A CRS tells R where on Earth your coordinates sit and what the units mean. Layers must share a CRS before you overlay, clip, or measure. Mismatched CRS is the single most common source of silent spatial errors.

Building Points from Scratch

library(sf)
set.seed(591)

stations <- data.frame(
  site_id  = sprintf("S%02d", 1:n),
  easting  = runif(n, 280500, 291500),
  northing = runif(n, 5180500, 5191500),
  effort   = sample(20:60, n, replace = TRUE)

# Promote the data frame to a spatial object

                         coords = c("easting", "northing"),

Note

st_as_sf() moves the two coordinate columns into a geometry column and leaves every other column as an ordinary attribute. An sf object is a data frame — nrow(), $, and subset() all still work.

Note

st_intersects() returns a list of matches for each feature. lengths(...) > 0 converts that to a plain logical vector, which is the safest way to subset. st_within(), st_contains(), and st_touches() follow the same pattern.

Distances Between Points

dm <- matrix(as.numeric(d), nrow = nrow(stations))
diag(dm) <- NA                                   # ignore each point's distance to itself

nnd <- apply(dm, 1, min, na.rm = TRUE)

round(summary(nnd), 0)

hist(nnd,
     breaks = 8,
     col = "#DFD1A7", 
     border = "#333333",
     xlab = "Distance to nearest station (m)",
     main = "Nearest-neighbour distances")

Most stations sit within about 1–2 km of their closest neighbour. If you were designing a real array you would compare this against the species’ home-range diameter to judge spatial independence.

Buffers, Union, and Hull

buf  <- sf::st_buffer(stations, dist = 1000)   # 1 km around each station
core <- sf::st_union(buf)                      # dissolve overlaps into one shape
hull <- sf::st_convex_hull(sf::st_union(stations)) # smallest convex polygon containing all points

round(as.numeric(sf::st_area(core)) / 1e6, 1)  # sampled area, km2
round(as.numeric(sf::st_area(hull)) / 1e6, 1)  # array footprint, km2

plot(sf::st_geometry(hull),
     border = "#1D3C34",
     lwd = 3, 
     lty = 2,
     axes = TRUE, 
     main = "1 km buffers, dissolved, inside the convex hull")
plot(sf::st_geometry(core), add = TRUE, col = "#BBDDE6", border = "#333333")
plot(sf::st_geometry(stations), add = TRUE, pch = 19, col = "#70002E")

The dashed green outline is the convex hull of the array; the pale blue shape is the area within 1 km of any station. The ratio of the two is a rough measure of how completely the array covers its own footprint.

Simulating an Elevation Surface

library(terra)

set.seed(591)

elev <- terra::rast(nrows = 60, 
                    ncols = 60,
                    xmin = 280000,
                    xmax = 292000,
                    ymin = 5180000,
                    ymax = 5192000,
                    crs  = "EPSG:32612")

# Two Gaussian ridges plus noise
xy <- terra::xyFromCell(elev, 1:ncell(elev))
d1 <- sqrt((xy[, 1] - 284000)^2 + (xy[, 2] - 5189000)^2)
d2 <- sqrt((xy[, 1] - 289500)^2 + (xy[, 2] - 5183000)^2)

values(elev) <- 1300 +
  900 * exp(-(d1 / 3200)^2) +
  600 * exp(-(d2 / 2600)^2) +
  rnorm(ncell(elev), 0, 30)

names(elev) <- "elev_m"
elev
Note

rast() defines the grid geometry, i.e., extent, resolution, and CRS before any values exist. values()<- fills the cells row by row from the top-left. res(elev) confirms each cell is 200 × 200 m.

Mapping the Raster

plot(elev, 
     col = terrain.colors(50),
     main = "Simulated elevation (m)",
     plg = list(title = "m"))

# Overlay the sf points by converting them to a SpatVector
plot(terra::vect(stations),
     add = TRUE, 
     pch = 19, 
     cex = 1.1,
     col = "#333333")
Tip

vect() converts an sf object to terra’s SpatVector; st_as_sf() converts back. That pair is how you move between the two packages.

Two high ridges rise to roughly 2,200 m and 1,900 m out of a 1,300 m valley floor. Dark points are the survey stations from the previous section.

Map Algebra and a Raster Stack

Rasters behave like numbers — you can add, multiply, and threshold them directly.

set.seed(591)

noise <- terra::rast(elev)                     # empty raster, same grid
values(noise) <- rnorm(terra::ncell(elev), 0, 6)

# Canopy declines with elevation, then is clipped to 0-100%
canopy <- terra::clamp(95 - 0.045 * (elev - 1300) + noise, 0, 100)
names(canopy) <- "canopy_pct"

# Distance from every cell to the stream
stream_v <- terra::vect(stream)
dist_str <- terra::distance(terra::rast(elev), stream_v)
names(dist_str) <- "dist_stream_m"

covs <- c(elev, canopy, dist_str)
covs

plot(covs, col = hcl.colors(50, "Viridis"), nc = 3)

Three panels: elevation, canopy cover, and distance to the stream. All three share the same grid, so they can be stacked and used together.

Neighbourhoods and Terrain

# 5 x 5 moving-window mean removes the simulated noise
elev_smooth <- terra::focal(elev, w = matrix(1, 5, 5), fun = mean, na.rm = TRUE)
names(elev_smooth) <- "elev_smooth"

slope <- terra::terrain(elev_smooth, v = "slope", unit = "degrees")

par(mfrow = c(1, 2))
plot(elev_smooth, col = terrain.colors(50), main = "Smoothed elevation (m)")
plot(slope, col = hcl.colors(50, "Inferno"), main = "Slope (degrees)")
par(mfrow = c(1, 1))

Smoothing removes the pixel-level noise so terrain() returns a realistic slope surface. Steepest values ring the flanks of each ridge; the summits and the valley floor are flat.

Note

focal() is the workhorse for scale questions: change the window size and you change the grain at which a covariate is measured, which often matters more to a habitat model than the covariate itself.

Reclassifying into Categories

rcl <- matrix(c(   0, 1500, 1,

                1900, 5000, 3),
              ncol = 3, byrow = TRUE)

freq() reports the cell count in each band, and each cell is 200 × 200 m, so multiplying by 0.04 converts directly to km².

Cropping, Masking, and Resampling

reserve_v <- terra::vect(reserve)

elev_res <- terra::mask(terra::crop(elev, reserve_v), reserve_v)

# Coarsen from 200 m to 800 m cells
elev_coarse <- terra::aggregate(elev, fact = 4, fun = mean)

res(elev)
res(elev_coarse)

par(mfrow = c(1, 2))
plot(elev_res, col = terrain.colors(50), main = "Clipped to wilderness unit")
plot(terra::vect(reserve), add = TRUE, border = "#1D3C34", lwd = 2)
plot(elev_coarse, col = terrain.colors(50), main = "Aggregated to 800 m cells")
par(mfrow = c(1, 1))

crop() cuts the extent down to the polygon’s bounding box; mask() then sets everything outside the polygon itself to NA. You almost always want both.

Reprojecting a Raster

elev_ll <- terra::project(elev, "EPSG:4326")

terra::crs(elev_ll, describe = TRUE)$name
round(as.vector(terra::ext(elev_ll)), 4)
round(terra::res(elev_ll), 6)          # now in degrees, not metres

plot(elev_ll,
     col = terrain.colors(50),
     main = "Elevation in longitude and latitude")
Important

Reprojecting a raster resamples it: cell values are interpolated onto a new grid, so the result is not identical to the original. Reproject vectors when you can and rasters only when you must, and use method = "near" for categorical rasters so classes are not averaged into nonsense.

Extracting Raster Values at Points

station_covs <- terra::extract(covs, terra::vect(stations), ID = FALSE)

site_data <- cbind(sf::st_drop_geometry(stations)["site_id"], station_covs)
head(site_data)

# Covariates are correlated - always check before modelling

Elevation and canopy cover are strongly negatively correlated by construction, which is exactly the collinearity you would flag before fitting a model with both.
